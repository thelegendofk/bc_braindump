# Sources and the layer each one owns

Use a source only for its layer. If two sources seem to disagree, check first whether they
answer different layers.

| Layer | Source | What we take | What we leave |
|---|---|---|---|
| L1 | Daniel Jackson, *The Essence of Software* | Concepts with one purpose, own state and actions, the operational principle | Formal synchronization notation |
| L2 | Johnson and Henderson, *Conceptual Models* (2nd ed. 2024) | Objects, attributes, operations; the rule that the model excludes layout and widgets | Long-form documentation templates |
| L2 | Sophia Prater, OOUX / ORCA | Objects, Relationships, Calls to action, Attributes as a worksheet | The full workshop format |
| L3 | Daniel Rosenberg, *UX Magic* (Semantic Interaction Design) | Grammar as the conceptual model; object-action matrix; sparse grid as cognitive load | Mapping onto a specific pattern library |
| L4 | Alan Cooper, application posture | Sovereign, transient, daemonic; posture sets the chrome budget | Older desktop specific advice |
| L5 | Material Design 1, Environment | A 3D space, every object has one z position | Elevation values and shadow specs |
| L5 | Apple, Liquid Glass (WWDC25) | Controls and navigation as a functional layer above the content | Glass materials, platform visuals |
| L6 | Ben Shneiderman, direct manipulation | Continuous representation of objects, physical actions instead of syntax, rapid reversible actions | |
| L6 | Don Norman, *The Design of Everyday Things*, revised edition | Affordance is what is possible, a signifier shows how people discover it | |
| L7 | Apple, *Designing Fluid Interfaces* (WWDC18) | Motion that is responsive, interruptible and redirectable | Platform gesture specifics |
